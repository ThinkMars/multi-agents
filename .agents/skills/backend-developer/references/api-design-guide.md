# RESTful API 设计规范（C3 通用，跨栈）

> 本规范与语言无关：Java + Spring Boot 与 Python 产出同样风格的 C3。

## 资源与路径

- 路径：`/api/v<主版本>/<资源复数名词>`，如 `/api/v1/tasks`；
- 资源名用名词不用动词，kebab-case：`/api/v1/task-items`；
- 嵌套不超过两层：`/api/v1/tasks/{taskId}/comments`；
- 禁止在路径里放动作：用 `POST /api/v1/tasks/{id}/complete` 表达非 CRUD 动作（动词只允许出现在最后一段）。

## HTTP 方法语义

| 方法 | 语义 | 幂等 |
|---|---|---|
| GET | 查询，不改变状态 | 是 |
| POST | 创建 / 非幂等动作 | 否 |
| PUT | 全量替换更新 | 是 |
| PATCH | 部分更新 | 否 |
| DELETE | 删除 | 是 |

## 状态码

| 码 | 用途 |
|---|---|
| 200 | 查询 / 更新成功 |
| 201 | 创建成功（响应体含创建结果与 Location） |
| 204 | 删除成功，无响应体 |
| 400 | 参数错误（业务错误码细分） |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 冲突（唯一约束、状态冲突） |
| 422 | 语义正确但无法处理（如业务规则拒绝） |
| 500 | 服务端错误 |

## 错误响应体（统一格式）

```json
{
  "code": 40001,
  "message": "任务标题不能为空",
  "data": null
}
```

- 业务错误码分段：`4xxxx` 客户端错误，`5xxxx` 服务端错误；错误码表随 C3 一并维护；
- message 面向用户可读，禁止把堆栈暴露给客户端。

## 请求 / 响应约定

- 时间用 ISO 8601（`2026-10-17T13:45:11+08:00`），金额用分为单位的整数；
- 布尔字段禁止用 0/1；枚举用字符串；
- 列表响应统一分页结构：`{ items, total, page, pageSize }`；
- 分页参数：`page`（从 1 开始）+ `pageSize`（默认 20，最大 100）；
- 排序参数：`sort=createdAt,desc`；过滤参数与字段同名。

## 版本与兼容

- 版本走 URL 路径（`/api/v1/`），破坏性变更升主版本并保留旧版至少一个迭代；
- 非破坏性变更（新增字段、新增可选参数）可次版本内进行，但必须在 C3 变更记录中登记；
- 认证统一 JWT（Authorization: Bearer <token>），令牌过期时间在 C3 注明。

## 编写要求

- C3 必须用 OpenAPI 3.x 描述，模板见 `api-doc-template.md`；
- 每个操作必须有：summary、至少一个 2xx 响应、错误响应、请求示例；
- 交付前用 `scripts/validate_openapi.py` 校验。
