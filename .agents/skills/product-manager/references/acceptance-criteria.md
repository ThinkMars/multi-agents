# C2 验收标准编写指南

> 契约编号：C2 · 生产者：产品经理 · 消费者：测试（全员评审参考）
> 形式：内嵌于 C1 PRD 第 6 节，或独立 AC 清单。每条 AC 必须有唯一编号（AC-01、AC-02…）。

## 编写原则

1. **可度量**：避免"体验流畅""快速响应"等模糊表述，改为可量化或可观察的标准；
2. **可测试**：每条 AC 都能被测试角色直接转成至少一条测试用例；
3. **无歧义**：一个 AC 只描述一个行为，不叠加多个场景；
4. **全覆盖**：P0 功能必须有 AC；P1/P2 可只写关键路径；
5. **含异常**：除正常路径外，覆盖主要错误路径（输入非法、网络失败、权限不足）。

## 格式：Given / When / Then

```
Given <前置条件：系统状态、用户状态、数据状态>
When  <触发动作：用户操作或系统事件>
Then  <预期结果：可观察的输出、状态变化、提示>
```

## 示例

| 编号 | Given | When | Then |
|---|---|---|---|
| AC-01 | 用户已登录且任务列表为空 | 用户输入"买牛奶"并点击添加 | 列表出现该任务，状态为未完成，输入框清空 |
| AC-02 | 用户未登录 | 访问任务列表页 | 跳转登录页，提示"请先登录" |
| AC-03 | 用户已登录 | 输入为空直接点击添加 | 不创建任务，提示"任务内容不能为空" |

## 自检清单

- [ ] 每条 AC 有唯一编号，且与 C1 功能清单交叉引用
- [ ] 每条 AC 可转成明确步骤的测试用例
- [ ] 覆盖正常路径 + 主要异常路径
- [ ] 无模糊词（最好、尽快、流畅、合理）
- [ ] P0 功能 100% 有 AC 覆盖
