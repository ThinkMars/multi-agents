# 跨栈组件设计原则

适用于 React / Vue / Flutter / Electron / 小程序所有栈的通用约定；分栈细节以对应规范为准。

## 单一职责

- 一个组件只做一件事：展示、交互、数据编排至少拆分其一到不同层级；
- 组件超过 **600 行**或包含 3 个以上不相关关注点时应拆分（行数是兜底信号，优先按关注点拆分）。

## 命名

| 类型 | 规范 | 示例 |
|---|---|---|
| 组件 | PascalCase | `TaskList`、`TaskItem` |
| 页面 | 领域 + 场景 | `TaskListPage` |
| 事件处理 | handle + 动作 | `handleSubmit` |
| 布尔 props | is/has/can 前缀 | `isLoading`、`hasError` |

## 入参出参

> 术语说明：本文「props」为泛称，指各栈组件入参（React / Vue 的 props、Flutter 的构造参数、小程序的 properties）。

- props 显式定义类型与默认值，必传 / 选填明确；
- 事件名用领域动词：`onTaskComplete` 而非 `onClick2`；
- 禁止把整个数据源对象无脑透传，按需传字段。

## 状态完备性（每个数据驱动组件必须处理）

1. **加载态**：骨架屏 / loading，禁止白屏等待；
2. **空态**：引导文案 + 主操作按钮，禁止空白列表；
3. **错误态**：可读的错误信息 + 重试入口；
4. **边界态**：超长文本截断、极端数据量、慢网络降级。

## 可访问性

- 可交互元素有可访问名称（按钮有文字，图标按钮配无障碍标签与提示）。
- 颜色不用作唯一信息载体（状态同时用文字 / 图标表达）；
- 文字对比度满足 WCAG AA（正文 4.5:1）。

## 复用判断

- 出现第 3 次相似代码再抽象，避免过早设计；
- 跨页面复用 → 提到公共组件目录（Web 惯例 `components/`，按栈调整，如 Flutter 的 `widgets/`）；单页面复用 → 页面内私有子组件；
- 通用组件禁止包含业务文案与业务请求。

## 常见反模式

- 上帝组件；props 层层透传超过 3 层（改用组合或各栈的跨组件状态方案，如 store / Context / provide-inject）；样式硬编码散落；错误处理只有 console.log 没有用户可见反馈。
