# 需求评审清单

交付 C1 前逐项自检，全部通过方可交付；评审人按同一清单复核。

## 完整性

- [ ] 背景与目标清晰，成功指标可度量
- [ ] 目标用户与核心场景明确
- [ ] 功能清单含优先级（P0/P1/P2）
- [ ] 交互说明覆盖关键流程与异常分支
- [ ] 非功能需求已定义（性能 / 安全 / 兼容 / 可用性）
- [ ] 验收标准完整，P0 功能 100% 覆盖

## 清晰性

- [ ] 无模糊词（最好、尽快、流畅、合理、优化）
- [ ] 术语统一，无同义不同名
- [ ] 每条需求只有一个含义，不可拆出多个理解

## 可测试性

- [ ] 每条 AC 可转成测试用例
- [ ] 边界与异常路径有明确预期
- [ ] 数据量级、精度单位明确（如"最多 200 字符"）

## 一致性

- [ ] 功能清单与验收标准编号交叉引用一致
- [ ] 交互说明与功能清单无矛盾
- [ ] 与既有需求 / 既有契约（C3/C4 旧版本）无冲突

## 可行性

- [ ] 无超出当前技术栈能力的需求（如有，已标注风险）
- [ ] 外部依赖已识别并给出对策
- [ ] 工作量可在一个迭代内完成（如超出，已建议拆分）

## 交付格式

- [ ] 版本号正确，变更记录已更新
- [ ] 存放路径符合规范：`docs/prd/<日期>-<名称>-v<版本>.md`
- [ ] 已通知下游角色（前端 / 后端 / 测试）消费
