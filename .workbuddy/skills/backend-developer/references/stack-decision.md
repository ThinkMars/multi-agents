# 后端技术栈选型决策树

## 决策流程

```
是否有存量 Java 体系 / 企业级合规要求？
├─ 是 → Java + Spring Boot
└─ 否 → 继续
是否数据密集型 / 需集成 AI 模型 / 追求极快交付？
├─ 是 → Python（FastAPI 首选）
└─ 否 → 继续
团队主要技术背景？
├─ Java 背景 → Spring Boot
├─ Python 背景 → Python
└─ 混合 / 无偏好 → 默认 Spring Boot（生态与可维护性）
```

## 对比表

| 维度 | Java + Spring Boot | Python（FastAPI / Django） |
|---|---|---|
| 适用规模 | 中大型、高并发 | 小中型、快速迭代 |
| 生态 | 企业级生态最全 | 数据 / AI 生态最强 |
| 开发速度 | 中等 | 快 |
| 性能 | 高（JVM 优化成熟） | 中等（异步场景足够） |
| 类型安全 | 强（编译期） | 中（FastAPI + Pydantic 可补） |
| 运维成本 | 中（JVM 调优有门槛） | 低 |
| 招聘 / 存量 | 企业主流 | 数据团队主流 |

## 硬性规则

1. **不擅自换栈**：项目已有栈必须延续；引入新栈需在技术方案中论证并告知全员；
2. **一个服务一个主栈**：禁止同一服务内混用两种语言（脚本工具除外）；
3. **契约与语言无关**：无论选哪个栈，C3 用 OpenAPI 3.x、C4 用 SQL DDL + ER，规范完全一致。

## 框架选择（Python 方向）

| 场景 | 框架 |
|---|---|
| API 服务（默认） | FastAPI（异步、自动 OpenAPI） |
| 重后台 / ORM / 管理界面 | Django |
| 轻量微服务 / 已有 Flask 存量 | Flask |
